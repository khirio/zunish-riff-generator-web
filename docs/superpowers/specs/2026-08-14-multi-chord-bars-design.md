# 1小節複数コード対応 設計書

## 背景・目的

現在の生成モデルは「1コード = 1小節」を前提にしている（`ChordProgression.romans` の各要素が丸ごと1小節分の右手・左手を生成する単位）。この前提を拡張し、1小節に2つのコード（それぞれ2分音符=2拍）が入る進行にも対応できるようにする。3コードからなる進行なら、1・2番目のコードを2分音符（合計1小節）、3番目のコードを全音符（もう1小節）として演奏する、という形が典型例。

メロディ（右手）はコードの境目を厳密に跨がなくてよく、むしろ跨いだ方がZUNらしい自然なフレーズになる。伴奏（左手）は逆に、各コード区間ごとに独立して伴奏パターンを選び、その区間の拍数に比例縮小して演奏する。

## スコープ

- コードの音価は **全音符（4拍）** と **2分音符（2拍）** の2種類のみに対応する（3連符や1拍刻みなどは対象外、YAGNI）。
- 既存の3コード進行5つ（`iv_v_vim`, `vim_v_iv`, `vim_v_ii`, `vim_iiim_ii`, `iv_v_vi_picardy`）に、「1・2番目を2分音符、3番目を全音符」とした姉妹進行を新IDで追加する。元の全音符版はそのまま残す。
- 著名リフ（7sus4アルペジオ、アリスアルペジオ）は、小節内の先頭コードの品質・ルートのみで発動判定し、発動したら常に固定のフル小節長でそのまま鳴らす（2つ目のコードの有無・種類は無視する）。
- 左手伴奏は、小節内の各コード区間ごとに独立して伴奏パターン・ボイシングを抽選し、その区間の拍数に比例縮小して演奏する。

## データモデル拡張（`content/progressions.py`）

`ChordProgression` に `beats: tuple[float, ...]`（`romans` と同じ長さ、パラレル）を追加する。`_register()` で `beats` 未指定の場合は `romans` と同じ長さの `(BEATS_PER_BAR,) * len(romans)` を自動補完し、既存9進行は無変更で動作する。

`BEATS_PER_BAR`（現在 `generator.py` にある `4.0`）は `theory.py` に移し、`generator.py` と `content/progressions.py` の両方から参照する。content配下のモジュールが `generator.py` に依存しないレイヤリングを保つため。

`validate()` に以下を追加する：

- 各 `beats[i]` は `{BEATS_PER_BAR, BEATS_PER_BAR / 2}` のいずれかである。
- `romans`/`beats` を先頭から走査し、累積拍数が `BEATS_PER_BAR` に達するたびに0にリセットする。累積が `BEATS_PER_BAR` を超えて別のコードにまたがることは不正（例: `(2, 4, 2)` のような並びはエラー）。
- 1周（`romans` 全体）の合計拍数が `BEATS_PER_BAR` の倍数であること。

この検証により、2分音符のコードは常に同じ進行内の隣接するコードとペアになって小節を完結させ、進行のループ・別進行への遷移は常に小節頭で揃う（プログレッション境界をまたいで2分音符が浮くケースは発生しない）。

## 新規コード進行

対象の5進行それぞれに、`beats=(BEATS_PER_BAR/2, BEATS_PER_BAR/2, BEATS_PER_BAR)` を持つ姉妹進行を新ID（例: `iv_v_vim_2bar`）で追加する。

- 姉妹進行の `follows` は元進行のものをそのまま引き継ぐ（下流の遷移の多様性を保つ）。
- 元進行の `follows` に、姉妹進行への遷移エントリを追加する（重みは同じ辞書内の他候補と同程度）。これにより姉妹進行が実際の生成ストリームに出現するようになる。
- `start_weight` は元進行と同程度の値を設定する。

## Director（`director.py`）

`_chord_stream` は `(tonic, roman_token)` に加え `beats` も yield するように拡張する。

新たに、このコード列を「合計拍数が `BEATS_PER_BAR` に達するごとにグループ化する」段を挟む（例: `_bar_stream`）。1グループが1小節分の `[(roman_token, beats), ...]`（要素数1または2）になる。`ChordProgression.validate()` の保証により、このグループ化は常に進行内で完結し、進行の切り替わり・ループ境界と小節境界が必ず一致する。

`bars()` は、このグループ単位でチードのトニック（グループ内では不変）と小節内コードリストを取り出し、`generate_bar`（後述、旧 `generate_slot`）を呼ぶ。左手アンティシペーションの先読み用に「次の小節の先頭コード」の `(tonic, roman_token)` を渡す（対象が「単一コードのトニック・ローマ数字」から「小節先頭コードのそれ」に一般化されるだけで、渡す情報の形は変わらない）。

## Generator — 右手（`generator.py`）

`generate_slot` を `generate_bar` に改名し、単一の `roman_token` ではなく `chords: list[tuple[str, float]]`（`[(roman_token, beats), ...]`、合計 `BEATS_PER_BAR`）を受け取るようにする。

- **リフ判定・発動**：`chords[0]`（小節内の先頭コード）の品質・ルートのみで `_pick_riff_or_none` を実行する。リフが選ばれた場合、これまでと同じロジック（固定モチーフを `chords[0]` のルート/オクターブに移調し、8分音符間隔で最後の音だけ小節末まで伸ばす）でフル小節分そのまま生成する。`chords` に2つ目のコードがあっても無視する。
- **スケールウォーク**（リフ非採用時）：リズムパターンの抽選は小節全体（4拍分）に対して1回のみ行う（コード境目を考慮しない）。スケール（装飾音プール用）の抽選も小節に1回。
  `chords` から各コード区間の開始・終了拍とその区間のコードトーンプール・装飾音プールを事前に構築し、リズムパターンの各オンセット（開始拍）がどの区間に属するかで、その拍のコードトーンプール・装飾音プールを決定する。
  区間が切り替わった直後のオンセットでは、直前に鳴らしたピッチに最も近い新コードトーンプール内の音へ乗り継ぎ、そこから通常のウォーク（-2/-1/+1/+2ステップ）を継続する。これにより、リズムそのものはコードの境目を無視して小節全体に敷かれる一方、ピッチはコードが変わった瞬間に自然に追従する。ノートの発音時間がコード境目をまたいで伸びることも許容する（意図的に分割しない）。
  ダイアド付加（`_add_dyads`）も、各ノートの発音開始拍が属する区間のコードトーンプールを使って和声音を選ぶ。

## Generator — 左手（`generator.py`）

小節内の各コード区間ごとに、伴奏パターン（block/broken）とボイシングを個別に抽選し、その区間の拍数（2拍または4拍）に比例縮小して演奏する。

- `_left_hand_events` に、対象区間の拍数（`duration_beats`、デフォルト `BEATS_PER_BAR` で既存動作と一致）と小節内での開始オフセット（`start_offset_beat`、デフォルト `0.0`）を渡せるようにする。
  - `block` 種：区間のボイシングを `duration_beats` 分だけサステインする（従来の「小節全体サステイン」の一般化）。
  - `broken` 種：32分音符換算の各ノート長を `duration_beats / BEATS_PER_BAR` の比率でスケールしてから配置する（従来の「1単位=1/8拍」が「1単位=(duration_beats/BEATS_PER_BAR)/8拍」になる一般化）。
- 小節内の各コード区間についてこれを個別に呼び出し、結果を開始オフセットをずらして連結する。

なお `_apply_left_hand_anticipation` と `generate_slot` の `next_minor_tonic_pc`/`next_roman_token` 引数は、現状の実装では実際には呼び出されていない（将来の右手メロディ機能向けに用意されたまま未結線の状態）。この設計では新たに結線はしない（スコープ外）。`generate_bar` は同じ形のまま `next_minor_tonic_pc`/`next_roman_token`（＝次小節の先頭コード）を受け取れるようにし、既存の「受け取るが使わない」プラースホルダー的な扱いをそのまま引き継ぐ。

## テスト方針

- `content/progressions.py` の `validate()` に対するユニットテスト（不正な `beats` 配列の検出）。
- 新規5進行の登録内容（`beats`、`follows` 配線）のテスト。
- `director.py`：複数コード小節が正しくグループ化され、`generate_bar` に渡る `chords` の形・小節境界・次小節先頭コードの先読みが期待通りであることのテスト。
- `generator.py`：
  - `generate_bar` の既存の単一コード小節での振る舞い（後方互換）を維持することの回帰テスト。
  - 2コード小節でのリフ発動（先頭コードのみで判定、フル小節長で発動）のテスト。
  - 2コード小節でのスケールウォーク時、各区間でコードトーン・装飾音プールが切り替わること、禁則音（b6）・ドリア6度のルールが区間ごとに正しく適用されることのテスト。
  - 2コード小節での左手伴奏が、各区間の拍数に比例縮小されて演奏されることのテスト。
  - 既存の単一コード小節向けテスト（禁則音、ダイアド、アポジャトゥーラ、左手ボイシング等）はシグネチャ変更に追従して更新する。
